## 一、Memory 动态加载触发点

`memory-search-mcp` 不是固定前置阶段，而是由测试过程中识别的特征触发的上下文驱动调用。**各工具的具体触发时机写在各自的 tool description 里，本处不重复罗列**（检索：memory_search / memory_get_methodology / memory_get_industry_case；沉淀：memory_save）。工具加载时可随时回看 description 判断该不该调。

唯一需要强记的纠偏：**禁止盲搜作为固定前置阶段（Phase 0）**。收到新目标时 agent 没有行业 / 技术栈 / 产品特征可做关键词搜索，盲目搜索只会得到空结果（"No results matching"），不构成有效加载。Memory 检索必须挂在 fingerprint-finder / API 探测 / 漏洞模式识别之后按需触发，不构成独立的"Phase 0"。

**原则**：每个触发点都是独立决策，不必按固定顺序；遇到未知 / 相似的特征就加载，禁止未检索就直接发请求；工具返回结果中的 `[[双向链接]]` 继续按链接加载关联 memory。

## 二、Memory 与模型推理的关系（避免被 memory 束缚）

memory 是经验补充，不是测试边界。理解这两者的关系决定 agent 是否具备真正的测试能力：

- **memory 无结果**（搜索返回空 / 目标类型从未沉淀）：agent 继续测试，使用模型自身的渗透测试知识与推理。空结果只表示"没有先例可参考"，不代表"目标无漏洞可测"。绝不被空结果阻塞。
- **memory 部分覆盖**（只找到 1-2 条相关 memory）：agent 同时使用 memory 沉淀经验 + 模型自身推理。memory 不覆盖的部分仍然要按通用方法测；只测 memory 列出的项就是"只测已知"，这是不完整的测试。
- **memory 与模型推理冲突**：以模型推理为准，前提是推理有合理依据。memory 只是过去的经验，可能因目标版本 / 部署环境差异而失效。测试完成后把新发现 / 纠正沉淀进 memory。
- **思维发散原则优先**：memory 给出的思路是起点不是终点。多个低危组合 / 跨漏洞链式利用 / 非常规入口（如二维码、客服系统、文件上传）仍要主动探索。

> 正确的心智模型：memory 是"先辈踩过的坑和走通的路"，模型推理是"基于通用安全知识 + 当前目标上下文的独立判断"。两者互补，不要用 memory 替代推理。

│  ├─ CMS 指纹识别                                                │

                                │
                                ▼
